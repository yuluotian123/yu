# NPC 行动检查点与恢复

更新：2026-10-23。已实现现场行动保存、关卡卸载／重载、继续游戏和实时读档恢复。NPC 自主跨关卡旅行、离屏推进和精度切换续接仍属后续阶段。

## 配置

1. NPC 使用稳定的 PersistentId，启用 `AiAgentComponent3D.Persist` 与 `CharacterDataComponent3D.Persist`。
2. 带移动的角色同时启用 `CharacterPersistenceComponent3D.Persist` 和 `RestorePosition`；继续使用已有移动与导航组件。
3. Goal、手动 Plan、选择器与 Action 连线保持现有配置。运行时计划、行动实例身份和检查点由系统生成，无需新增 Plan 变量或手工填写检查点编号。
4. 可恢复执行图使用唯一 Entry、串行 Action Sequence、Success Return。支持前往输入地点、等待图内时长、计算图内数值、请求对象交互；允许失败直接返回失败。连接不能含条件、并行或循环，不跨子图恢复。
5. “休息”使用等待节点计算时长，结束后通过 Action Results 改变角色需求；占用床位在目标输入的资源要求里配置 `capacity`。计时期间不提前发放最终收益。Action 的高级预算 `TimeoutSeconds` 要大于本步移动与等待的总时长，恢复不会重置超时。

技能、动画、副作用记忆／关系／情绪节点、自定义节点、条件分支、并行和子图仍可正常执行；包含这些内容的行动存档时明确标记 `Replan:UnsupportedExecution`，读取后重新规划。不会把任意执行图假定为可安全恢复。

## 保存内容与恢复规则

- 保存当前 Goal／Plan、剩余 Action 顺序、选择器节点绑定、本步冻结输入、执行起始事实和已计算数值。各 NPC、本次计划与行动拥有独立实例身份。
- 等待保存总时长和已执行秒数。多个等待分开记录；完成的等待不会重做。已加载场景内的抽象移动保存旅行时长与进度；近处移动使用角色存档恢复实际位置，再请求新路径。
- 完成的移动步骤不会重放。导航路径、Flow 栈、原生 Node、组件实例与资源租约不会写入检查点。
- 关卡切换先采集所有存档 section，再取消现场任务。恢复推迟到角色数据、对象和关卡就绪；未完成移动等待导航就绪，最长等待 5 秒。
- 重新校验 Plan 适用条件、对象和 Action 前提，重新申请占用。目标已失效、配置签名改变、数据不合法、容量冲突或导航缺失时取消并重规划；不会换成另一个目标继续原步骤。
- 原来源只负责选取候选。恢复不要求重新感知原对象，也不因“当前位置”查询变化而重新选目标；对象当前条件和能力仍按执行规则校验。
- 超时计时包含保存前已执行的时间。离屏或关闭游戏的时间不补算。

## 提交边界

对象交互节点先验证并排队；只有整个 Action 成功、结果与租约通过最终校验后才修改对象和角色。主线程同步完成这次提交，并记录行动实例身份；已提交步骤不会进入剩余队列，遇到带相同提交标记的边界检查点也会跳过。

原子存档同时保存世界对象、角色数据和行动标记。此保证覆盖受支持的公共交互与 Action Results，不扩展到自定义节点的任意外部副作用。重复读取同一个存档会一起恢复这些参与者，不把早期行动检查点单独套在更晚的业务状态上。

NPC agent section 使用 schema 3；旧 schema 不恢复行动，重新规划。世界 section 仍为 schema 3。F8 → NPC → 状态可查看“行动恢复”状态和事件日志；暂停 AI、手动重规划和现有 LOD 切换仍会明确取消当前计划。

## 示例

**休息 60 秒**：同一床位选择器连接“前往床位”和“休息”两个 Action；后者申请 `capacity`，执行图等待 60 秒，`TimeoutSeconds` 设为 90，Results 降低疲劳。等待 25 秒保存后，读档重新申请床位并继续剩余 35 秒，结束时发放一次效果。

**按库存计算取货数量**：图内计算 `units = min(input.target.stock, 2)`，等待 `units * 5` 秒，再请求同一目标的 `take_stock(units)`。等待 4 秒保存后，冻结的数量仍为 2，总时长仍为 10 秒；恢复后再等 6 秒，成功时才扣库存。库存不足时操作失败并重规划。
